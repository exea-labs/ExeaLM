# Data

We train the 0.1B model on about 100B tokens. Why 100B, the post-training sets and every license are in
[DATA.md](../DATA.md). This page covers the sources, the two candidate pretraining mixes, and the scripts in
`exealm/data/`, all of which run on a laptop.

## Two candidate mixes (about 100B tokens each)

`python -m exealm.data.sources` prints both. Choosing between them, or blending them, is a job for small ablations:
train the `small` preset on each and compare.

**Candidate A: DATA.md's mix (English-heavier).**
- English web: 47.5%
- code: 15%
- reference, academic, books and PDFs: 10%
- math and science: 10%
- reasoning and synthetic: 5%
- multilingual (Japanese, Chinese, Korean): 5%
- QA and instruction-style text: 2.5%
- annealing: 5%

Details in [DATA.md](../DATA.md).

**Candidate B: mix proposal v0 (Japanese-heavier).** It was written for a 2T-token pool and is scaled to 100B with
every share kept (`MIX_V0` in `sources.py`):
- **Japanese, about 21%:** the cleanest LLM-jp Japanese, with extra weight on Wikipedia, Aozora Bunko, KAKEN and Diet
  minutes.
- **English, about 49%:** FineWeb's best-scoring educational pages, plus books, papers and encyclopedias.
- **Math and code, about 11%.**
- **K2 Horizon, about 20%:** web and QA, plus reasoning and behavior data, mostly saved for the final decay phase.

Questions the ablations should answer:
- How much Japanese is right for a model this small? More Japanese makes it better at Japanese and worse at English.
  This is an experiment to run, not an opinion to hold.
- Does candidate B's heavier use of curated sources (Wikipedia, books, KAKEN) beat candidate A's larger web share?
- K2 Horizon token counts are still guesses, since nobody has counted them yet.

At 100B tokens nothing needs repeating: we select from roughly 40T available.

## Scripts

| Script | What it does |
|---|---|
| `sources.py` | Both candidate mixes as data, plus the LLM-jp sub-corpora and K2 Horizon subsets with their licenses. |
| `download.py` | Fetches a sample: LLM-jp files directly (no account), or any Hugging Face dataset by streaming. |
| `quality.py` | Rule-based filters (with separate rules for Japanese) and exact deduplication. |
| `dedup.py` | Near-duplicate removal across all sources: MinHash LSH (word 5-grams, character 5-grams for Japanese), CPU only. |
| `tokenizer.py` | Trains a byte-level BPE tokenizer on a sample. |
| `pack.py` | Tokenizes documents into one flat token file per split, keeping document boundaries. Retrieval needs them so it can skip the document being read. |
| `loader.py` | Training batches: random windows, the document id of each position, and swarms ([swarms.md](swarms.md)). |

## Try it on a sample

```bash
# 1. download a sample (a few hundred MB)
python -m exealm.data.download llmjp --subset ja/ja_wiki --max_files 1 --out data/raw
python -m exealm.data.download hf --repo IFM/TxT360-v2 --config web-high-medium --max_rows 20000 --out data/raw

# 2. filter + exact dedupe
python -m exealm.data.quality data/raw/*.jsonl.gz --out data/filtered

# 3. near-duplicates across all sources (the first copy wins, so list the best source first)
python -m exealm.data.dedup data/filtered/*.jsonl.gz --out data/dedup

# 4. tokenizer (on a sample of the mix)
python -m exealm.data.tokenizer data/dedup/*.jsonl.gz --vocab 49152 --out tokenizer

# 5. pack into a flat token file with document boundaries (hold out a file as validation)
python -m exealm.data.pack data/dedup/<train files> --tokenizer tokenizer --out data/packed/train
python -m exealm.data.pack data/dedup/<val file>    --tokenizer tokenizer --out data/packed/val

# 6. train the 17M "small" model on it (laptop or a free Colab GPU)
python -m exealm.train.pretrain --preset small --data data/packed/train --val data/packed/val --seq 256 --steps 2000
```

### Held-out benchmark inputs for decontamination

`python -m exealm.data.benchmarks` exports exclusion text using explicit schemas,
not the generic training-data extractor. Install `pip install -e '.[data]'` first.

| Export name | Dataset | Configuration / split | License stated by dataset card |
|---|---|---|---|
| `hellaswag` | [Rowan/hellaswag](https://huggingface.co/datasets/Rowan/hellaswag) | default / validation | Not confirmed in card metadata; review upstream terms before redistribution |
| `arc_easy` | [allenai/ai2_arc](https://huggingface.co/datasets/allenai/ai2_arc) | ARC-Easy / test | CC-BY-SA-4.0 |
| `arc_challenge` | [allenai/ai2_arc](https://huggingface.co/datasets/allenai/ai2_arc) | ARC-Challenge / test | CC-BY-SA-4.0 |
| `mmlu` | [cais/mmlu](https://huggingface.co/datasets/cais/mmlu) | all / test | MIT |
| `gsm8k` | [openai/gsm8k](https://huggingface.co/datasets/openai/gsm8k) | main / test | MIT |
| `humaneval` | [openai/openai_humaneval](https://huggingface.co/datasets/openai/openai_humaneval) | openai_humaneval / test | MIT |
| `jcommonsenseqa` | [sbintuitions/JCommonsenseQA](https://huggingface.co/datasets/sbintuitions/JCommonsenseQA) | default / validation | CC-BY-SA-4.0 |

HellaSwag and JCommonsenseQA use their public validation sets. ARC includes separate
Easy and Challenge exports. These selections must match the evaluation being
reported; they do not cover private tests, other splits or benchmark variants.
Dataset cards and their licenses were checked on 2026-11-14. Exported benchmark
text is for exclusion, never added to a training mix or committed to this repository.

```bash
python -m exealm.data.benchmarks --benchmark gsm8k --out data/benchmarks/gsm8k
python -m exealm.data.pack data/benchmarks/gsm8k/text.jsonl.gz \
  --tokenizer tokenizer --out data/benchmarks/gsm8k-packed
# Feed gsm8k-packed to exealm.data.decontam's --benchmark gsm8k=... option (PR #41).
```

Repeat with each export name in the table. Resolve `main` to a dataset commit before
streaming, or pass `--revision COMMIT` to reproduce an earlier export. Each new output
directory contains `text.jsonl.gz` plus a manifest recording the resolved revision,
source URL, split, row and segment counts, stated license, and compressed-file SHA-256.
`--limit 3` is useful for a smoke test; it always sets `sample: true` and provides no
claim of full benchmark coverage. Omit `--limit` for a full split. A malformed row
fails the export with its index; partial exports are not published and existing
outputs are not overwritten.

Raw questions, every answer option, GSM8K reasoning/answers, and HumanEval prompts,
solutions and test text are preserved as separate documents. HellaSwag also includes
each context-plus-ending; HumanEval includes prompt-plus-solution to catch code
spanning that boundary. Code is treated purely as text and never executed. Unrelated
answer options are never joined into an artificial n-gram. This is an explicit raw
field policy, not a claim to reproduce every harness prompt template or normalized
benchmark variant. Exact token-overlap filtering retains the limitations documented
by the decontamination tool, especially short segments and paraphrases.
